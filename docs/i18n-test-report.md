## 5. Search and filtering (real browser, shipped behaviour)

`node scripts/test-search.mjs` runs the built pages in headless Chromium with JavaScript
enabled and reads the resulting DOM. Search matches Thai names, English names **and**
scientific names from either locale — the search haystack is locale-independent by design.

```
✓ th  'ข้าว' (Thai name)             visible= 1 said="พบ 1 รายการ" emptyState=hidden
✓ th  'Oryza sativa' (scientific)    visible= 1 said="พบ 1 รายการ" emptyState=hidden
✓ th  'สุกร' (animal, Thai)          visible= 1 said="พบ 1 รายการ" emptyState=hidden
✓ en  'rice' (English)               visible= 1 said="1 items" emptyState=hidden
✓ en  'ข้าว' (Thai query on EN page) visible= 1 said="1 items" emptyState=hidden
✓ en  'tilapia' (English)            visible= 1 said="1 items" emptyState=hidden
✓ th  'tilapia' (English query on TH page) visible= 1
✓ en  'zzzz' (no match → empty state) visible= 0 said="0 items" emptyState=shown
✓ th  (empty query → everything)     visible=12 said="พบ 12 รายการ"
```

This test found a real defect during development: a Thai query on an English page returned
0 results because filtering used only the locale-resolved name. Fixed by giving each result a
locale-independent `data-haystack` (Thai + English + scientific + common names + tags) instead
of patching the two locales separately.

## 6. Missing-translation handling

Both fallback directions ship as fixtures and are asserted by the QA gate, so the policy
cannot silently regress:

| State | Fixture | Observed |
| --- | --- | --- |
| Thai record only | `plants/mungbean-thai-only` | Thai page renders normally; **EN page shows the Thai source text with the "original language" badge**; record is not hidden |
| English record only | `research/cover-crop-trial` | EN page renders normally; **TH page shows the English source text with the badge** |
| No localization at all | — | renders the explicit "no data" label, never a blank box |

Gate assertions: `fallback-badge` (badge present on the locale that lacks the text) and
`fallback-directions` (both directions actually exercised) in `scripts/qa-site.mjs`.

No machine translation is present anywhere: every string is either authored Thai/English UI copy
or a demo/placeholder record, each carrying `reviewStatus` + `provenance`
(see `docs/LOCALIZED-CONTENT-CONTRACT.md`).

## 7. Typography checks

- Thai display headings do not break mid-word at 1440 / 834 / 390 px (phrases are wrapped in
  non-breaking spans; verified on screenshots `docs/screenshots/th-home-*.png`)
- English display headings and long scientific names (`Capsicum annuum L.`, `Musa × paradisiaca L.`)
  render on their own lines with `lang="la"` and the italic serif stack
- No horizontal overflow at 390 px on home / catalogue / detail / search
- No webfonts are downloaded, so no text ever reflows after first paint

### Intentional bilingual affordance

The English search field's placeholder reads `Try: rice, ข้าว, Oryza sativa` — the Thai example
is deliberate (it advertises that Thai queries work from the English UI) and is not a missing
translation. Everything else on English pages is English, asserted by the QA gate.

## 8. Verdict

**i18n: PASS** — 8/8 acceptance points from the bilingual directive are met and machine-checked:
all routes in both locales, no untranslated UI labels, no broken locale links, correct
canonical/hreflang pairs, search works with Thai/English/scientific names, missing translations
handled transparently, no fabricated translations, both locales build and pass visual QA.
